## 4. Pièges connus (payés aux Sprints 1 et 2)

- Les env `SUPABASE_ANON_KEY`/`SUPABASE_SERVICE_ROLE_KEY` de l'Edge Function ne sont **pas** les JWT legacy des clients : ne jamais réintroduire une comparaison stricte seule ; `verify_jwt = true` (config.toml) est ce qui garantit la signature de la claim `role`.
- Le MCP Supabase `execute_sql` tourne en `supabase_read_only_user` : il ne peut pas appeler les fonctions `rag` fermées ; `apply_migration` fonctionne ; les journaux de l'EF se lisent par `query_logs` (`source = 'function_logs'`).
- 4 fichiers Bessières sans L0 : toute stratégie en L0 seul les perd (c'est ce qui a coûté un rejeu complet au Sprint 2).
- `node -e "…"` dans un Bash : les backticks du texte sont interprétés par le shell → écrire le script dans un fichier (Write) puis l'exécuter. Un heredoc bash décode `\u0300` en caractère réel : vérifier en octets.
- `\b` JavaScript ne borne pas devant une lettre accentuée : `(?<![a-zà-ÿ])`.
- `out_project_identity` sans `name` ; CCAG hors projet (`layer='app'`) ; `\m`/`\M` Postgres et `_` ; `.or()` PostgREST sans virgule ni parenthèse, `imatch` ; `REFUSAL_PATTERNS` à compléter si une nouvelle formulation de refus est voulue ; ~200 conversations créées par campagne dans `rag.conversations` (purge sur demande d'Eric seulement).
- Le juge de fidélité est instable d'un passage à l'autre (C5 0,75 → 0,25 sur le même code) : jamais un seul passage.
