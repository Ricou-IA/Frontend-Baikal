## 4. Pièges connus (Sprint 3 et précédents)

- **gemini-2.5-flash sans réflexion boucle sur un caractère** (espaces, puis tirets une fois la règle de forme posée) dans les tableaux/cellules denses ; la garde générique (`MAX_REPEAT_RUN` = 200) coupe le flux mais ne corrige rien — une réponse tronquée reste un échec. Tester `gemini_thinking_budget` sur un petit échantillon avant une campagne complète.
- **Le juge est déterministe à T=0** (fait établi, écart-type 0,000 sur 3 passages) : un seul passage suffit ; l'instabilité vue au Sprint 2 venait de la variance des réponses entre campagnes.
- **`npx supabase secrets list` montre des empreintes, pas les valeurs** — vérifier la présence de `COHERE_API_KEY` par cette commande, jamais en demandant la valeur en clair dans le chat.
- **Les campagnes réelles durent 5-6 min** : toujours en détaché ; ne jamais lancer deux campagnes en parallèle sur le même projet (variance de latence faussée).
- **Eric commite en parallèle sur `main`** (docs/contrats, console) : jamais `git add -A`, chemins explicites uniquement.
- 4 fichiers Bessières sans L0 : toute stratégie en L0 seul les perd — vérifier après S4.2 que `synthesis`/`comparison` et la recherche ciblée (déjà en L0 + L1 depuis v2.2.0) retrouvent bien ces fichiers.
- Les env `SUPABASE_ANON_KEY`/`SUPABASE_SERVICE_ROLE_KEY` de l'Edge Function ne sont **pas** les JWT legacy des clients : le rôle se lit dans la claim `role` du JWT (`verify_jwt = true`) — ne jamais réintroduire une comparaison stricte seule.
- Le MCP Supabase `execute_sql` tourne en `supabase_read_only_user` : il ne peut pas appeler les fonctions `rag` fermées ; `apply_migration` écrit ; les journaux de l'EF se lisent par `query_logs` (`source = 'function_logs'`).
- `\b` JavaScript ne borne pas devant une lettre accentuée : `(?<![a-zà-ÿ])`.
- Un heredoc bash décode `\u0300` en caractère réel : écrire les fichiers avec l'outil Write, jamais `node -e`/heredoc pour du texte accentué.
- `eval_overrides.llm_model` n'est appliqué qu'en `service_role` — toute campagne doit s'authentifier avec la clé service_role, jamais anon/user.
